# Production reliability implementation and evidence

## Identity and scope

Repository: `atreasureboy/ovolv999_coding`. Implementation baseline: `183cb2b2a8be3ba47fcc519cb554559dae1ba526`, 2026-09-28. This batch follows `codex_production_prompt.md` and `production_audit.md` supplied from the user's local `ovocoding` directory. It preserves the prior permission, outcome, worktree and cancellation contracts. Changes and rollback commits are local; this batch does not push, publish packages, change credentials, or configure remote branch protection.

Builds identify the source commit, dirty state, source SHA256, package version, Node version and build time in `dist/build-info.json`. The final tarball identity and installed smoke results are recorded in `.artifacts/production/release-package-smoke.json`. Runtime data has independent schema versions: Session v2, background metadata v1, RunStore v1, workspace lease v1 and diagnostic event v1. Build identity is not a runtime-data schema version.

Target contract: trusted users, one Windows or Linux host, Node 22.13.0/22.x/24.x, local filesystems, same runtime-state location for every cooperating process. This workstation ran Windows with Node 24.20.0. Linux and the other Node matrix entries require their own CI evidence. NFS/SMB, cross-host coordination, mixed old/new concurrent writers and hostile extensions are unsupported. `isolated-worker` fails closed on both OS branches. No Job Object, container or cgroup isolation is claimed.

## Resource ownership and recovery

| Resource | Owner and lifetime | Persistence and recovery entry |
| --- | --- | --- |
| Session | Explicit CLI/resume owner; save checks birth identity and revision | Session directory/history v2; `claimSessionOwnership`, `loadSession`, `saveSession`; corruption is retained |
| Workspace/Git | Family within process plus shared local lease; physical promises extend hold | Runtime `workspaces/*.json`; `--runtime-status` and explicit `--recover-workspace` |
| Tool action | RunStore operation ID before side effect; terminal receipt after observed completion | Runtime `runs/*.json`; absent/unknown receipt is never interpreted as no effect |
| Background CLI | Independent supervisor, verified worker/descendants and output handles | Atomic metadata, `stopSession`, background stop CLI; stop_failed/unknown retained |
| Background tool | BackgroundTaskManager and registered physical-resource promise | Async stop/dispose waits for verified known tree; failed resources retained |
| MCP | McpModule connection owner across turns; client owns request/queue/child lifecycle | Bounded health/readiness and explicit disposal; unsupported protocol rejected |
| Provider request | Shared gateway admission slot and token reservation through stream completion | Process-local health/usage; deadline/cancel releases reservation conservatively |
| Diagnostics | EventLog/Daemon log owner; best-effort append and bounded rotation | Health reports failure; neither log is authoritative recovery state |

Operation order is lease → durable intent → effect → physical completion/receipt → final verification/finalizers → final accepted artifact/outcome → release. Exceptions with an uncertain write preserve a recovery obligation. A timeout or dead owner does not prove descendants stopped. Cancellation status can be returned with explicit unfinished resources; it is not a physical-stop receipt.

## Minimal runbook

1. **Stop incomplete:** check background metadata and verified process identities. `stopping` is a request still in progress; `stop_failed`/unknown retains resources. Do not delete metadata or reuse the workspace merely because the CLI exited. Stop known descendants with the OS tools only after checking identity; unresolved descendants require operator inspection.
2. **Workspace/Run unknown:** run `ovolv999 --runtime-status <workspace>`. Preserve the runtime directory and outputs. Inspect missing receipts, actual processes and external service receipts. After all physical operations have stopped, use `ovolv999 --recover-workspace <workspace> --epoch <observed-epoch> --decision keep|cancel|continue --confirm-physical-stop`. The command computes the current artifact version, rejects a live/unverified owner and records the choice. `keep` retains quarantine; `cancel`/`continue` release the workspace. None replay a command, delete artifacts, fabricate receipts or automatically continue an old Run.
3. **Persistence lock:** new locks recover only a verified dead/mismatched local identity. Unknown legacy owners remain blocked. Inspect the named lock and process; do not mass-delete lock directories. Run one program version against a data directory at a time. Keep crash artifacts for diagnosis.
4. **Storage unavailable/full:** stop admitting side effects, preserve journals and workspace changes, restore storage capacity, then inspect/reconcile. Diagnostic failure is visible but can degrade independently; failed critical intent persistence must prevent effects. Total retention must be managed operationally until a tested retention policy exists.
5. **429/provider storm:** inspect gateway queue/breaker/usage health; reduce admission or wait for Retry-After/circuit reset. Cancel queued work where appropriate. Do not replay a partially streamed run or switch provider/data residency implicitly.
6. **History corrupt/unknown schema:** preserve the original file, inspect the diagnostic path and recover from a compatible backup. Do not overwrite with an older executable. Multimodal messages must remain arrays.
7. **Upgrade/rollback:** stop new admission and confirm physical worker termination, copy runtime data and workspace changes, retain old package/hash, install the candidate separately and smoke test fixtures. Roll back executable plus compatible data backup; retain newer data separately. See `release-support.md`.

This batch is a candidate for supervised, trusted-user Windows internal testing after the final local checks pass. It is not a formal production-release approval and not an isolated multi-tenant Worker.
